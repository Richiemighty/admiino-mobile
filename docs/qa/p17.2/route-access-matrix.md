# Route and deep-link access matrix

| Destination                                  | Required state                                                      | Mobile boundary                                                                       | Backend revalidation                               | Status                                                      |
| -------------------------------------------- | ------------------------------------------------------------------- | ------------------------------------------------------------------------------------- | -------------------------------------------------- | ----------------------------------------------------------- |
| Home, Tasks, Teams, Projects, Calendar, More | Authenticated active workspace                                      | Six tabs remain visible; content/actions are permission-aware                         | Workspace membership/effective permissions         | PASS (mobile tests)                                         |
| Inbox                                        | Authenticated active workspace                                      | Canonical `/inbox`; protected route does not fall through to Home                     | Workspace-scoped notifications and target lookup   | PASS (mobile tests); live NOT RUN                           |
| Search                                       | Authenticated active workspace                                      | Screen only renders within authenticated shell                                        | Search service workspace scope                     | PASS (source); live NOT RUN                                 |
| Task detail                                  | Authenticated + task access                                         | 401 signs out, 403/404 shows safe task error, 423 suspends                            | `getTaskReadAccess` on `GET /tasks/:id`            | PASS (source/mobile tests)                                  |
| Task edit/create                             | Effective create/edit permission and task access                    | Form does not submit without permission; server errors remain authoritative           | `POST /tasks`, `PATCH /tasks/:id`                  | PASS (mobile tests); live NOT RUN                           |
| Task conversation/files                      | Collaborate/edit access                                             | Attachment/comment controls are conditional; authenticated download service is reused | Task access and attachment authorization           | PASS (source); collaboration contract limitation documented |
| Project detail/members/files                 | Project visibility or active project membership                     | Project member/file errors are distinct from empty states                             | `findAccessibleProject` and file access            | PASS (mobile tests); live NOT RUN                           |
| Project create/edit                          | Effective project permission/governance or project admin membership | Create/edit controls use effective permissions and active member status               | Project controller authorization                   | PASS (mobile tests); live NOT RUN                           |
| Approvals                                    | Owner/admin or manager category authority                           | Categories are role-gated; unauthorized users see no approval queue                   | Approval service/controller checks                 | PASS (mobile tests); state changes NOT RUN                  |
| Profile/settings                             | Authenticated account                                               | Protected account route redirects signed-out users                                    | Session/account APIs                               | PASS (source/tests)                                         |
| Workspace switch                             | Authenticated user with eligible membership                         | Cache/auth state is cleared or replaced before new workspace content                  | Workspace membership + effective permission reload | PASS (auth/cache tests)                                     |
| Suspended/access-denied                      | 423 or permission load error                                        | Dedicated recovery screen; no stale workspace content                                 | Backend status/permission response                 | PASS (mobile tests)                                         |

Direct URL, notification target, navigation history and cached-screen paths are not authorization substitutes. The client intentionally relies on each resource service's backend response and does not grant access from a hidden button.
